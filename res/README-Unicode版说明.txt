■ 概要

  原版 OREMO 使用 Tcl/Tk + Snack 编写，所有文本文件都以“系统代码页”读写，
  因此在简体中文 Windows (GBK) 上会把日文 Shift_JIS 的录音表读成乱码，
  并用乱码作为 wav 文件名保存。
  本版本完全重写了程序，在保持界面、功能、设置窗口与原版一致的前提下：

  - 内部全部使用 Unicode，wav 文件名直接使用 Unicode 保存
  - 读取录音表 / 发声类型表 / 备注 / 引导BGM设置 / ust 时自动识别编码
    (BOM、UTF-8、UTF-16、Shift_JIS、GBK、Big5)
  - oto.ini、备注、录音表、初始化文件的写出编码可以设置
    (默认 Shift_JIS，与 UTAU 兼容；出现无法表示的字符时自动改用 UTF-8(BOM) 并提示)
  - 内置“文字编码／文件名 转换工具”
  - 界面语言：日本語 / 简体中文 / English (工具 → 界面语言，重启后生效)

■ 文件

  oremo.exe        ... 主程序
  korede.exe       ... 引导BGM设置文件制作工具 (原 guideBGM/korede.exe)
  reclist*.txt     ... 录音表 (原版附带，Shift_JIS，会被自动识别)
  typelist.txt     ... 发声类型表
  guideBGM/        ... 节拍器咔嗒声、引导BGM及其设置文件
  message/ja|zh_CN|en/ ... 界面文字 (UTF-8，与原版 message/*.tcl 格式相同)
  oremo-setting.ini ... 系统设置 (autoSaveInitFile 与原版相同；另存编码、语言、修正开关)
  oremo-init.tcl    ... 退出时自动保存的设置 (格式与原版相同，可互相读取)

■ 与原版的兼容性

  - oremo-init.tcl、message/*.tcl、引导BGM设置文件、备注文件(OREMO-comment.txt)、
    setParam 形式备注、oto.ini 的格式全部与原版相同。
  - 快捷键、菜单、右键菜单、各设置窗口与原版相同。
  - 命令行: oremo.exe [-saveDir 文件夹] [-script 初始化文件] [拖放的文件夹]
  - 原版读取的旧版英文翻译文件，可放在 message/ 下并在 oremo-setting.ini 写 lang=custom 使用。

■ 面板大小的独立调整 (新增)

  波形 / 频谱 / 响度 / F0(音高) 四个面板可以分别调整高度：
  把鼠标移到面板的下边界 (光标变为 ↕)，按住左键上下拖动即可。
  只改变所拖动的面板，其余面板大小不变，窗口高度随之自动增减。
  (原版的 Shift+鼠标滚轮 调整方式仍然可用；拖动窗口边框时仍由最下方的面板吸收变化)

■ 录音表 / 发声类型表宽度的自由调整 (新增)

  把鼠标移到录音表(或发声类型表)的右边缘 (光标变为 ↔)，按住左键左右拖动即可。
  (原版的 Ctrl+鼠标滚轮 调整方式仍然可用)

■ 录音时实时显示 (新增)

  录音开始后，波形 / 频谱 / 响度 / F0(音高) 四个面板每秒约刷新10次，实时显示正在录制的声音。
  (原版由 Snack 实时更新波形和频谱；本版四个面板都实时更新。
   录音中的F0为增量计算，录音结束后会对整段重新精确计算。)

■ 高分辨率(4K)屏幕 (新增)

  程序已声明支持高DPI，在4K等高分辨率屏幕上文字和图形都按实际分辨率清晰绘制，
  不再被Windows放大而发虚。字体、面板、图标按Windows的缩放比例自动放大。
  工具 → 界面缩放      : 自动 / 100% ～ 300%，觉得字小时可调大 (重启后生效)
  工具 → 高分辨率屏幕清晰显示 : 取消勾选即恢复原版的显示方式 (重启后生效)
  旧的 oremo-init.tcl 中保存的面板大小会自动换算，显示的实际大小保持不变。

■ 字体 (新增)

  录音表、录音项、备注栏的字体会自动选择“能显示列表中全部文字”的字体
  (例如简体中文录音表会自动使用微软雅黑，避免日文字体缺字导致字体混杂)。
  也可在「选项 → 字体大小设置」的「字体」中手动指定，更改立即生效。

■ 新增菜单「工具」

  文字编码设置...                  读取/写出时使用的编码
  以指定编码重新读取录音表          自动识别错误时，手动指定编码重新读取
  文字编码／文件名 转换工具...
     - 文件内容编码转换 : 批量把 txt/ini/ust 等转换为指定编码 (可预览、可备份)
     - 修复乱码文件名   : 例如在中文系统上解压日文 zip 得到的
                          「扨撈壒傪暪梡偡傞昁梫桳.txt」→「単独音を併用する必要有.txt」
                          用原版在中文系统上录出的「偁.wav」→「あ.wav」 (可预览、可撤销)
     - 修复字符串       : 粘贴乱码文字，列出可能的原文
  界面语言
  BUG修正设置...                   见下

■ 实现上的差异 (重写后自然消失的问题，不影响兼容性)

  - 不再使用 Snack / oremo-recorder.exe / oremo-player.exe / modifyPre.exe 等外部程序，
    录音与播放改用 PortAudio (sounddevice)，MFCC 修正在程序内计算。
    因此不再在 tools/ 下生成临时文件，从其他目录启动也能正常使用自动修正2。
  - 初始化文件只解析 set 命令，不再作为 Tcl 脚本执行。
  - 消息中的路径含空格、%、[ 时不会再被截断或出错。
  - 24bit/32bit/浮点录音统一按 16bit 刻度显示与计算。
  - 自动录音中 BGM 事件以采样精度触发 (原版依赖定时器)。
  - 音频I/O设置中的「Snack」一栏对应 Windows MME 设备；增益为软件增益。
  - 修正了原版消息文件中的笔误 t(saveCommentList,errMsg)]。

■ BUG修正开关 (工具 → BUG修正设置)

  以下是原版的缺陷。默认开启 F06 以外的全部修正；F06 默认关闭 (保持原版行为)。
  取消勾选的项目与原版行为完全相同。
  F01 空录音表时切换等会报错的操作加保护
  F02 单独音oto.ini生成会覆盖当前显示的波形 (未保存录音丢失/存成错误音名)
  F03 快捷键「停止自动录音」被绑定到手动停止而不起作用
  F04 重新设置快捷键时解除旧按键
  F05 详细设置「取消」会把窗口打开期间切换的录音位置也回滚
  F06 能量/F0/自动推定/MFCC修正使用 wav 实际采样率 (原版用设置值或固定44100Hz)
  F07 引导BGM设置文件的时间单位 sample 无法使用
  F08 初始化文件中「[」每次保存增加「\」、含「;」时整个文件被拒绝读取
  F09 保存并恢复音频I/O设置
  F10 从 ust 生成列表时排除休止符 R 和空歌词
  F11 有其他声音播放时，音叉/BGM试听/自动录音只改变状态但不发声
  F12 带修饰键的录音快捷键，先松开修饰键时录音不停止
  F13 更改采样率会改写当前音频的采样率(播放变速)
  F14 「读取备注文件」按取消会清空全部备注并在退出时删除备注文件
  F15 生成oto.ini前的确认中按「取消」仍会打开生成窗口
  F16 连续音oto.ini：有被排除的音拍时 MFCC 修正波及前一个 wav 的行
